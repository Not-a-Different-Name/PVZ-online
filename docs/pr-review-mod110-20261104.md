# MOD110 特效池、观战与等待边界修复

本轮保留并整合 moanlixin 的 PR [#2](https://github.com/Not-a-Different-Name/PVZ-online/pull/2)、[#3](https://github.com/Not-a-Different-Name/PVZ-online/pull/3)、[#4](https://github.com/Not-a-Different-Name/PVZ-online/pull/4)，补充双端适配和安全边界。此记录描述源码验收；现有 MOD110 R1 图形玩家包、CLI v1 附件尚未包含本轮修改。

- 修复 PC 按类型分离粒子后遗留空 attachment，以及挂载失败的无主装饰动画；混合容器中其他特效保留。安卓保留已有正确的按类型分离逻辑，并补挂载失败回收。
- 旧档在完整校验成功后，从植物、僵尸、投射物、钱币及场景的真实持有者追踪 attachment / reanimation 图。回收无主对象前断开引用，保护共享的存活动画。清理前以 `.effects-before-<fingerprint>.bak` 留存原输入；无法备份则跳过清理，读取过程不覆盖原档。格式、版本、网络协议和池容量均未变更。
- 容器销毁在递归前清空出边计数，防止循环引用在换场、清池或读档前清场时递归溢出；新槽位初始化全部特效字段，避免序列化未使用槽位的遗留值。
- 安卓 v4 读档先验证文件头和 CRC，再释放上一份特效图，随后载入各个池。避免旧容器析构时，按相同 ID 错杀已经恢复的新动画或粒子；无效 CRC 不进入释放流程。
- PC 诊断由 `PVZ_REANIM_STATS=1` 显式开启；默认不计数、不记录出生表、不运行专项全池扫描。Android 仅移植共用修复与现有绘制采样的实体数校正，没有移植 PC 诊断模块。
- 观战预测草坪里的僵尸进家时，仅移除该僵尸，不切换预测场景为失败；其他对象继续推进。真实玩家的漏怪传递与失败规则保持原逻辑。
- 选卡等待标记在网络会话或草坪撤销后及时清理，避免访问空会话。团队入口置顶前处理空控件列表。

## 验证

PC 原生完整 App 回归 351 项及特效专项 263 项均零失败。MuMu Android 15 的完整原生 App 回归与专项合计 610 项零失败；使用独立诊断身份与受控场景，正式及 manualquick APK、存档和设置保护核对一致。按依赖重编修改单元并链接完整 App，其他对象经源比对复用；未声称 clean 全编或新的正式 APK 验收。

保留的负例：原 R1 的泄漏专项分别失败 1 项；原 PR3 的循环引用样本崩溃，且共享动画样本将活僵尸动画标死。旧观战越界专项失败 2/5，旧等待空会话入口发生访问异常。最终候选在相同入口通过。安卓额外发现原生销毁循环导致栈溢出，已补递归边界并复验。

这些是实际引擎的构造场景和模拟器检查，未取得玩家原始崩溃栈、故障存档或自然长局前序。玩家对“等待队友闪退”的具体阶段不明确，本轮修复已确认的生命周期风险，不宣称全部历史闪退根治。服务器本轮无变更。
