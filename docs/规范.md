# 项目规范（pvz-online）

> 这不是建议，是**约束**。每一条都对应一次已经发生过的真实损失。
> 违反其中任何一条，都会重演「反复改但改不好」的循环。

---

## 1. 版本控制

| 规则 | 说明 |
|---|---|
| **一处改动 = 一个提交** | 禁止把多处未验证的修改打包提交 |
| **提交前必须 `git diff` 自查** | 不 `diff` 就等于不知道自己改了什么 |
| **提交信息写三件事** | 改了什么 / 为什么 / 怎么验证的 |
| **禁止提交未验证的改动** | 验证不过就 `git checkout -- <file>` 回退，别留着「以后再修」 |
| **仓库位置** | `<pvz-online 根>\re-plants-vs-zombies`（**在子目录里**，不在 `pvz-online` 根；本机即 `C:\Users\18611\Desktop\pvz-online\re-plants-vs-zombies`） |
| **工作分支** | `pvz-online`；不要直接提交到 `main` |
| **绝不入库** | `build-x86/`、`runtime/`、`third_party/` 的构建产物、任何 PopCap 素材 |

**起步命令**：

```bash
git -C re-plants-vs-zombies status
git -C re-plants-vs-zombies diff -- Lawn/Widget/GameSelector.cpp
```

---

## 2. 改动粒度

- **一次构建只验一处改动。** 无法单独归因的改动，不许进这次构建。
- 改动尽量**局部化、可摘除**，不要重排既有代码。
- 对上游文件的改动要**最小化**——把上游代码整段重写，等于放弃了将来跟上游合并的能力。

---

## 3. 验证手段（强制三件套）

**必须同时用**：截图 + 像素测量 + 运行时插桩。**禁止肉眼猜、禁止凭推理下结论。**

### 3.1 截图铁律

> **看不到 `client=800x600 OK 1:1` 的截图，一律视为无效证据。**

- 只用 **`tools/grab.ps1`**。它不移动、不缩放窗口，用
  `SetWindowPos(HWND_TOPMOST, SWP_NOMOVE|SWP_NOSIZE)` 提层（前台锁不拦），抓完恢复。
- **不要用 `run_and_shot.ps1` 的截图结果**：它从 DPI 不感知的 PowerShell 里
  `SetWindowPos(816,639)`，窗口被放大到 1020×799，800×600 的 framebuffer 被**拉伸 1.25×**
  → 图是假的（详见 `02-技术总结.md` §1）。
- **不要用 `shot.ps1 -ClientW/-ClientH` 去「掰回」尺寸**：那是在掩盖一次不该发生的 resize。
- `SetForegroundWindow` 会被 Windows **前台锁**拒绝；被拒绝时会**静默**抓到别的窗口
  （曾经抓到过终端）。提层请用 `HWND_TOPMOST`。

### 3.2 等待时间

- **截图前稳定等待 > 3 秒。** 菜单滑入动画 75 帧 ≈ 1.25 s，等不足就截到运动中间帧。
- 需要「静止姿态」时，等待时间要留足，并**用插桩确认**（例如打印 `slide=0`）。

### 3.3 像素测量

- 用 `tools/row_edges.ps1` 把截图转成「每行非底色连续段」，把画面矩形换算成精确坐标。
- **数字与画面必须互相印证**：插桩打印的矩形 == 截图量到的矩形，才算验证通过。

---

## 4. 插桩纪律

- 调试开关**统一 `PVZ_*` 环境变量前缀**。
- 插桩要**集中**，并带 `// @pvz-online debug` 标记，便于一次性摘除。
- **功能完成后必须清除插桩**，并同步删除调用它的测试脚本参数。
- 禁止把调试用的坐标偏移、`mVisible` 开关、`MarkDirty` 之类的「补丁」留在正式代码里
  —— 需要偏移就写**常量并注明理由**，不要留一个默认值为 0 的 env 开关。

---

## 5. 注释规范

| 场景 | 写法 |
|---|---|
| 原版二进制地址（上游已有） | `//0x452CB0` —— **保留，不要动** |
| GOTY 版偏移（上游已有） | `// GOTY @Patoke: 0x456150` —— **保留，不要动** |
| 上游贡献者标记（上游已有） | `// @Patoke: ...` —— 尽量保留 |
| **自己的改动** | `// @pvz-online: <原因>` —— **必须写为什么，而不是写做了什么** |

注释解释**为什么**，不复述代码。

---

## 6. 资源规范（法律红线）

- 游戏素材**只能**来自**用户合法拥有**的副本（本机为 Steam 正版 PvZ GOTY）。
- 素材只解包到**本地 `runtime/` 目录**，**仅供本机测试**。
- **PopCap 的资源绝不能随 mod 分发。** 发布 mod 时**只发代码**，玩家自备正版副本。
- **绝不上传** `main.pak` / `runtime/` / 任何解包素材到公开位置。
- 资源读取优先走 `main.pak`（`SexyAppBase.cpp:6118` 是活的），散装文件只是回退
  （`PakInterface.cpp:194-220`）。需要看原版素材用 `tools/pakx.pl`。

---

## 7. 窗口规范

- **绝不强制全屏。**
- **绝不劫持 / 夺取桌面窗口。**（曾经因为强行把屏幕切成 600×800 把桌面窗口管理器搞崩过。）
- 保持 **800×600 窗口化**。
- DPI 已用 `main.cpp` 里运行时绑定的 `SetProcessDPIAware()` 修好，**不要退回**。
- 测试脚本提层用 `HWND_TOPMOST` + `SWP_NOMOVE|SWP_NOSIZE`，抓完恢复；**不要抢焦点**。

---

## 8. 构建

```bat
:: <根> = pvz-online 目录（本机：C:\Users\18611\Desktop\pvz-online）
cmd /c <根>\build-msvc.bat            :: 增量
cmd /c <根>\build-msvc.bat reconfig   :: 删 build-x86 重新配置
```

- 目标名**固定**为 `SexyAppFramework.exe`，**别改**。
- 覆盖 `runtime/` 里的 exe **前必须先杀进程**：
  `taskkill //F //IM SexyAppFramework.exe`（否则 `Device or resource busy`）。
- 用 **VS2022 自带**的 CMake/Ninja；**不要**用裸 `cmake`（不在 PATH）。
- 平台固定 **x86 / 32 位**。

---

## 9. 排错心法

1. **先插桩取数，再改代码。** 不要从像素混杂物反推 z-order / alpha。
2. **一次只改一处**，改完立刻 `git diff` + 构建 + 1:1 截图。
3. **拿不准就先亲眼看美术本体**：`Shift+F11`（dump 所有已加载图到
   `%APPDATA%\...\_dump\`）或 `tools/pakx.pl extract`。
4. **矛盾时以最新实测为准。**（用户裁定：「一切以最新状态为准，前后矛盾按照后发生的为事实」。）
5. **回退不丢人，硬撑才丢人。** 验证不通过就回退，别叠补丁。
