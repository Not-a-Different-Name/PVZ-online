# 05 · 联机（M3 中继上公网）

> M3 把联机从"局域网直连"推到"**过公网中继**"：不用公网 IP、不用端口映射，2–6 人各自
> 连到一台中继服务器（Go，代码在 `server/relay/`，部署与运维见 `server/relay/README.md`），
> 服务器按席位转发游戏帧。**直连模式原样保留**（局域网还是老办法连）。
> 协议细节以 `Lawn/Online/NetProtocol.h` 的注释为准，本文件是导航。

## 一、这一版多了什么（相对 `04-联机-M2.md`）

| 项 | 说明 |
|---|---|
| 中继模式 | 面板多了 **Server 行**（默认已填云地址）+ **Code 行**：**Create Room** 建房拿 4 位房间码，**Join Room** 按码加入 |
| 双传输 | 会话有 DIRECT（老 Host/Join，直连 27777）与 RELAY 两条路；玩法逻辑不分叉——席位表、事件流、判胜判负是同一套 |
| 席位模型 | 1..6 号位完整席位表：进房取最小空闲席位；**房主 = 建房的那条连接**（换位后不跟席位走）；名册 / 漏怪链 / 换位环都按**上座席位**算，有空洞自动跳过；开局应答 `START_ACK`、判胜、选卡 `SEEDS_READY` 已按席位记账（多个席位不会等错人；2026-10-03 晚席位上限从 4 抬到 6） |
| 换位 | 谈判流程同 M2（对面按 Accept）；**落实由服务器做**——服务器交换两席映射后全房广播 `SEAT_SWAP`，所有人只认这条广播执行置换（天然免双重应用） |
| 保活反过来 | 直连是客户端互发心跳；中继下**服务器每秒 PING、客户端回 PONG**（客户端自身仍按"没有任何入站包"判死——MOD_BUILD 39 起放宽到 **15 秒**转自动重连，直连保持 5 秒；PING 就是那个包） |
| 掉线 | **席位保留 + 自动重连（MOD_BUILD 39）**：服务器 30 秒收不到某连接数据 → 席位保留 **60 秒**并广播 `PEER_OFFLINE`，期间掉线者自动重连（`REJOIN`）回来即续；保留过期 → 非主机广播 `PEER_LEAVE(reason=超时)`、**房主 → 全房 `ROOM_CLOSED` 散房**（房主掉线同样先保留，不再当场散房）。客户端 15 秒沉默转重连、总窗口 45 秒，超窗/按「取消并退出」才提示死因回主菜单 |
| 其余规则 | 漏怪链、全队败、暂停、退关、闯关换关……与 `04` §一 完全一致，不改 |
| 局内快捷聊天 | 场上按 **T**（快捷短语）/ **E**（植物表情）弹非模态面板、数字 1-8 选发（`MSG_QUICK_CHAT=16`，线路只传编号，文字/卡图各机本地查 `QuickChat.h`）；横幅显示约 3 秒；单机/选卡/过场完全不响应 |

## 二、怎么联机（中继，操作）

1. **两台机器 pull 同一提交并重新构建**（构建代次不同不拒连，但"行为一致"只在同版本下成立）。
2. 主机：主菜单点**第一槽大墓碑**（组队入口）→ 面板 **Create Room**（Server 框默认
   `101.200.131.182`，本地调试可改回 `127.0.0.1`）→ 状态行出现"已进房"，房间信息块显示
   `Room XXXX - you are P1 (host)` 和名册——**把 4 位房间码念给队友**。
3. 队友：同一入口 → 在 **Server + Code** 两框填好（码大小写随意）→ **Join Room**。
4. 连上后：名册 P1..P6 逐格亮起；**Swap** 与后一位换位（对面按 Accept）；重连/换房先按
   **Disconnect**。
5. 开局与 `04` §二 第 5 步起完全一样：大墓碑 = 组队闯关，PUZZLE 石板 = 单关局；
   房主开始 → 队友确认 → 一起进场。
6. **直连模式没删**：Host/Join + Host IP 框，局域网同一网段时用（端口 27777，走老路径）。

## 三、中继控制帧表

规则：**`0xF000` 以下是游戏帧**（服务器只读头两个字节 `src`/`dst` 做路由，逐字节透传）；
**`0xF000` 起是控制帧**（服务器自己处理，不走转发）。`SWAP_REQUEST`/`SWAP_REPLY` 这类
客户端之间的谈判属于游戏帧；谈妥后由 `SWAP_COMMIT` 请服务器落实。

| 帧 | 方向 | 说明 |
|---|---|---|
| `0xF001` WELCOME | S→C | 进房成功：你的席位 + 房主席位 + 房间码 + 全量名册（每席的名字与构建代次） |
| `0xF002` REJECT | S→C | 建房/加入被拒。原因：0=协议版本不符 / 1=没这个房间 / 2=满员 / 3=码格式不对 / 4=服务器忙 / 5=包不合法 / **6=重连时名字或构建和席位原主对不上 / 7=重连时房间已散或席位已释放** |
| `0xF003` PEER_JOIN | S→C | 有人进房（广播给房内其他人；新人自己的名册在 WELCOME 里） |
| `0xF004` PEER_LEAVE | S→C | 有人离开。原因：0=主动退 / 1=超时（30s 无数据，或席位保留到期） / 2=被服务器请出去 |
| `0xF005` ROOM_CLOSED | S→C | 房间解散：0=房主走了 / 1=服务器收摊。发完即断连 |
| `0xF006` SEAT_SWAP | S→C | 全房广播：两个席位已互换——**换位的唯一权威**，所有人只认它 |
| `0xF007` PING | S→C | 每秒一次保活（房里没人说话时唯一的入站流量） |
| `0xF008` PEER_OFFLINE | S→C | **有人掉线、席位进保留期**（MOD_BUILD 39）：带席位与剩余秒数；席位照旧占着（各等待门继续堵），保留到期才走 `PEER_LEAVE` |
| `0xF009` PEER_BACK | S→C | **掉线的人回来了**（MOD_BUILD 39，载荷同 PEER_JOIN）：队友据此提示并等回归者重报状态 |
| `0xF011` CREATE_ROOM | C→S | 建房（协议版本 + 构建代次 + 名字） |
| `0xF012` JOIN_ROOM | C→S | 按房间码加入（同上 + 4 位码） |
| `0xF013` SWAP_COMMIT | C→S | 换位已谈妥，请服务器落实并广播（带两个席位） |
| `0xF014` PONG | C→S | 回应 PING（零载荷） |
| `0xF015` LEAVE_ROOM | C→S | 主动退房（比直接断 TCP 语义清楚，服务器能立刻广播；**不留席位保留**） |
| `0xF016` REJOIN | C→S | **掉线重连请求**（MOD_BUILD 39）：房间码 + 席位 + 名字/构建，服务器对身份受理（防顶号，不做令牌）；受理后回 WELCOME、广播 `PEER_BACK` |

## 四、部署摘要（2026-10-03）

- 云实例：阿里云 **`101.200.131.182`**，中继监听 **TCP 97**（`systemd` 常驻、开机自启、
  `Restart=always`）；房间状态全在内存，重启即清空。
- 客户端默认值：面板 Server 框默认 `101.200.131.182`（`OnlineDialog.cpp`）；中继端口常量
  `DEFAULT_RELAY_PORT = 97`（`NetProtocol.h`；直连 `DEFAULT_PORT = 27777` 不动）。
- 验证：远程协议冒烟对云服务器全绿（建房/加入/转发校验/换位/回收/散房/各类拒绝）。
- 完整 runbook（构建、宝塔上传、systemd、防火墙三层、升级回滚、排障）→ `server/relay/README.md`。

## 五、版本纪律

- `MOD_BUILD`（M3 落地时 16→17；现 **39**）：**16 → 17 是中继落地**（新控制帧一族 + RELAY 会话路径。旧构建对
  中继一无所知——连不上 97 的服务器；直连模式下旧构建行为不变）；**17 → 18** 是闯关扩
  完整版（一局 5 关 → 25 关跨场景，关序号口径变了，旧构建收到 5 以上会建错关）；
  **18 → 19** 是局内快捷聊天（`MSG_QUICK_CHAT=16`）：旧构建把这帧当没见过的消息静默丢——
  发的人以为喊了、队友没看见；**19 → 20** 是闯关时长档走联机协议（START_LEVEL 加
  u8 runMode，载荷 17→18 字节：混搭时旧长度的开局命令按串包断线）。
  **20 → 39 各代次见 `04-联机-M2.md` §四链**；其中 **27 → 28** 是席位上限抬到 6 +
  顺位乘数改 2 的幂（**宽松过渡**——协议号不动，混版 ≤4 人房照连但两边乘数规则不同、
  5+ 人房旧包收 WELCOME 解析拒绝进不去；云中继需重部署 6 席版）；**30 → 31** 是队友
  场地查看（观战，新游戏帧族 17/18）：混搭时旧构建对这两帧静默丢、观看端 3 秒超时
  收场——**服务器/云中继零改动**（游戏帧逐字节转发）；**31 → 32** 是合成僵尸三件套
  （桶钢门 / 路障报纸 / 桶报纸）：漏怪帧 `MSG_ESCAPED_ZOMBIE` 会携带新枚举值
  34/35/36，旧构建解到表外类型会读穿僵尸定义表——两端同版本。
  **38 → 39 是掉线自动重连 + 席位保留**（新控制帧 `REJOIN`/`PEER_OFFLINE`/`PEER_BACK`
  + `REJECT` 原因 6/7；沉默判死 15s、重连窗口 45s、服务器踢人 10→30s、席位保留 60s）：
  **服务器可先行部署**——老客户端对没见过的控制帧静默丢（照常玩，只是掉线后等待变长到
  保留期）；新客户端配老服务器则 `REJOIN` 被吞、窗口耗尽走老路（特性失效但不出错）。
  `PROTOCOL_VERSION` 与 WELCOME 布局未动，直连路径不受影响（见 `03-过程与问题.md` §5.76）。
  判据沿用 `04` §四："混搭时会不会演岔" → 会，照纪律抬代次。
- `PROTOCOL_VERSION` 仍是 1（游戏帧包格式没动过；动的是"谁能参与中继/新行为"）。
- **不改默认地址/端口**这类纯连接层配置不需要动 `MOD_BUILD`。

## 七、已知缺口与留账（v1）

- **无鉴权 / 无 TLS / 猜码无速率限制**：房间码即门票（32⁴ ≈ 100 万），v1 接受；
  详见 `server/relay/README.md` §已知限制。
- **暂停是共识模型**：双方几乎同时按暂停/继续时，两边可能短暂不一致（各自先动、对端跟进，
  以最后收到的一条为准）；极端乱序时以先到的暂停为准。
- **等待窗口内新加入**：开局等待 / 选卡等待期间中途进房的人，不在"等谁"的记账范围内
  （等的是命令发出那一刻的上座席位）。
- **3–6 人实机未验收**：席位表在协议层 / `nettest` 已钉死（现上限 **6**），实机目前验收的是
  2 人；3–6 人过公网跑一局需要更多机器，列为后续验收项（云中继需先重部署 6 席版）。
- **重连不做令牌（MOD_BUILD 39）**：受理只认「房间码 + 席位 + 名字 + 构建」——防顶号靠
  名字/构建匹配。服务器重启 + 房间码复用 + 同名同构建的叠加概率极低，v1 接受不做闭环；
  席位原主在保留期内真被顶号同人（改名）会被 `REJECT 6` 拒（见 `03-过程与问题.md` §5.76）。
- **服务器重启 = 全体掉线**：无优雅退出、无状态落盘（有意的）；升级/重启挑没人的时候。
  （重连救不了这种：房间随重启没了，`REJOIN` 得 `REJECT 7` → 重连失败提示后回主菜单。）
