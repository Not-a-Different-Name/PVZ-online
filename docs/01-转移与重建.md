# 01 · 转移到另一台电脑 + 重新构建

> 目标：把项目搬到新机器后，能**一次构建成功**并跑起来。
> 历史上最容易踩的坑是**硬编码绝对路径**——已经在 8c4204e 全部迁移化（见 §2），新机器无需再改。

---

## 1. 必须一起搬走的东西

整个 `pvz-online` 目录一起拷（它本身就是自洽的），但下面这些**可以删掉**以省空间：

| 复制 / 跳过 | 相对路径 | 大小 | 说明 |
|---|---|---|---|
| ✅ **必需** | `re-plants-vs-zombies/`（**排除 `build-x86/`**） | 7 MB | 源码 + 完整 git 历史 + baseline 提交 |
| ✅ **必需** | `third_party/` | 31 MB | zlib / libpng / libjpeg-turbo 三个**本地** git 仓库（带 tag），被 CMake 相对路径（`${THIRD_PARTY_DIR}`）引用 |
| ✅ **必需** | `tools/` 里的脚本（`*.ps1` `*.pl` `*.cs`） | < 1 MB | 截图 / 探针 / pak 解包工具 |
| ✅ 本机必需 | `runtime/` | 89 MB | 解包后的游戏资源 + exe，见下方**法律声明** |
| ✅ 必需 | `build-msvc.bat`、`.gitignore` | 几 KB | 构建入口 |
| ❌ 跳过 | `re-plants-vs-zombies/build-x86/` | 251 MB | 构建产物，会重新生成；**且含旧机器的绝对路径，带过去反而会坏事** |
| ❌ 跳过 | `runtime/*.png` `runtime/*.log`（58 个） | 数十 MB | 测试截图与日志 |
| ❌ 跳过 | `tools/*.dmp` `tools/exe_disasm.txt` `tools/bass24x/` `tools/sw32.exe` `tools/bass24.zip` | ≈580 MB | 逆向 / 调试垃圾，可重新生成 |

**净体积：约 130 MB（不含 runtime）或 220 MB（含 runtime）。**

### 1.1 代码也可以直接从在线仓库拉（不拷硬盘）

**在线仓库（机器 2 的同步源）**：`git@github.com:Not-a-Different-Name/PVZ-online.git`
网页：<https://github.com/Not-a-Different-Name/PVZ-online>

```bash
git clone git@github.com:Not-a-Different-Name/PVZ-online.git   # SSH
cd PVZ-online && git checkout pvz-online                       # 开发分支（克隆默认落在 main）
git pull                                                        # 日常同步；推送用 github remote
```

- **仓库里只有代码与文档**：`third_party/`、`runtime/`、`main.pak` 都不在里面
  （法律边界见 §5）——新机器仍需拷贝 `third_party/`，素材自备（正版 Steam 副本）。
- `origin` 指向**上游** `Patoke/re-plants-vs-zombies`，**绝不要往它推**。

## 2. ✅ 绝对路径问题（已在 8c4204e 迁移化，新机器无需再改）

历史上这里有 4 处硬编码绝对路径（写死 `C:\Users\ThinkPad\...`），是上次搭建时的**唯一真正转移障碍**；
现已全部消除。下面记录当前的查找机制（出问题时按此排查）。

### 2.1 `build-msvc.bat` 怎么找 Visual Studio（自动）

脚本遍历 `C:\Program Files\Microsoft Visual Studio\2022\{Community,Professional,Enterprise}`，
取第一个存在 `VC\Auxiliary\Build\vcvarsall.bat` 的版本作为 `VSROOT`；都找不到就报错退出。
（本机 `vswhere.exe` 不存在，所以没依赖它。）
VS 装在**别的盘**或别的根目录（预览版等）时才需要改脚本。
若装了 vswhere，用它查实际路径：

```bat
"%ProgramFiles(x86)%\Microsoft Visual Studio\Installer\vswhere.exe" -latest -property installationPath
```

### 2.2 `re-plants-vs-zombies/SexyAppFramework/imagelib/CMakeLists.txt` 怎么找 third_party（相对）

```cmake
get_filename_component(THIRD_PARTY_DIR "${CMAKE_CURRENT_SOURCE_DIR}/../../../third_party" ABSOLUTE)
```

（`imagelib/` → `SexyAppFramework/` → 仓库根 → `pvz-online/`，所以是三级 `../`。）
三个 `ExternalProject` 的 `GIT_REPOSITORY` 都指向 `${THIRD_PARTY_DIR}/{libjpeg-turbo,zlib,libpng}`；
目录不存在时 CMake 配置阶段直接 `FATAL_ERROR`，报错会告诉你缺哪个。
**唯一要求：`third_party/` 与 `re-plants-vs-zombies/` 并列。**

### 2.3 `re-plants-vs-zombies/build-x86/`（CMake 缓存）

CMake 会把绝对路径烘进缓存（`CMAKE_HOME_DIRECTORY`、编译器路径等）。
**换机器后必须删除并重新配置**，不要拷贝：

```bat
cmd /c <pvz-online 根>\build-msvc.bat reconfig
```

## 3. 新机器环境要求

- **Visual Studio 2022**，必须勾选 **「使用 C++ 的桌面开发」** 工作负载（含 MSVC v143 x86 工具集 + Windows SDK）
- 不需要单独装 CMake / Ninja：脚本用的是 **VS 自带的**那份
  （`%VSROOT%\Common7\IDE\CommonExtensions\Microsoft\CMake\{CMake\bin\cmake.exe, Ninja}`）
- **不要**用裸 `cmake` 命令（不在 PATH 里）
- 目标平台固定 **x86 / 32 位**（`vcvarsall.bat x86`）；上游代码是 32 位的，x64 构建不通

---

## 4. 构建与运行

```bat
:: 首次 / 换了机器 / 改了 CMakeLists（<根> = pvz-online 目录）
cmd /c <根>\build-msvc.bat reconfig

:: 日常增量
cmd /c <根>\build-msvc.bat
```

产物固定为 `re-plants-vs-zombies/build-x86/SexyAppFramework.exe`（目标名固定，**别改**）。

**拷贝到 runtime 之前必须先杀进程**，否则报 `Device or resource busy`：

```bash
taskkill //F //IM SexyAppFramework.exe     # git-bash 写法
cp build-x86/SexyAppFramework.exe runtime/
```

**必须以 `runtime/` 为工作目录启动**（它靠这个找 `properties/resources.xml` 和 `main.pak`）。

## 5. ⚖️ 游戏资源与法律边界（重要，别搞错）

- 所有游戏素材来自**用户自己合法购买的 Steam 版 PvZ GOTY**，解包到本机 `runtime/` **仅供本地测试**。
- **PopCap 的资源绝不能随 mod 分发。** 发布 mod 时**只发代码**，让玩家用自己的正版副本。
  因此 `runtime/` 与 `main.pak` 在 git 里是**被忽略**的（见仓库 `.gitignore` 追加段与顶层 `.gitignore`）。
- **转移时**：`runtime/` 可以跟着硬盘一起搬（那是你自己的副本），但**不要**上传到网盘 / GitHub / 任何公开位置。

### 资源读取机制（曾把我误导过）

- `main.pak` **是在运行时真的被加载的**：`SexyAppFramework/SexyAppBase.cpp:6118`
  ```cpp
  gPakInterface->AddPakFile("main.pak");
  ```
- **散装文件只是回退**：`paklib/PakInterface.cpp:194-220`（`FOpen` 先查 pak 索引，查不到才 `fopen`）。
- ✔ **旧文档 `CLAUDE.md` 说「`AddPakFile("main.pak")` 被上游注释掉了」——这是错的，已修正**（4d8d4f5）。
- `bass.dll` 是音频库（BASS）；`bass21-steam.dll.bak` 是原版备份。

### pak 格式（`tools/pakx.pl` 已实现）

- 整文件**逐字节 XOR `0xF7`**；头部 `u32 magic = 0xBAC04AC0` + `u32 version = 0`
- 条目：`u8 flags`（`0x80` = 结束）/ `u8 nameWidth` / `name` / `i32 size` / `FILETIME(8)`
- 数据区紧跟在结束标记之后，按条目顺序拼接
- 文件名用**反斜杠**（`images\SelectorScreen_BG.jpg`），这是第一次写解包器时踩的坑

```bash
perl tools/pakx.pl runtime/main.pak list "SelectorScreen"
perl tools/pakx.pl runtime/main.pak extract 'reanim\SelectorScreen_BG_Right.jpg' runtime/_art
```
