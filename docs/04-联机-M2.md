# 04 · 联机（M2 双人局域网）

> 这一版是**联机玩法的最小可玩形态**：两台机器各跑一块同关卡的棋盘，
> 一块草坪上漏掉的怪**传到队友那块草坪上**——合作 PVE 的核心机制。
> 代码在 `Lawn/Online/`，协议细节以 `NetProtocol.h` 的注释为准，本文件是导航。

## 一、玩法规则（已定，别再改）

| 规则 | 说明 |
|---|---|
| 席位 | 主机 = 1 号位，客户端 = 2 号位。`MAX_PLAYERS = 4`，M3 扩到四个；名册 UI 一直画 4 行 |
| 漏怪是链 | 1 → 2 → 3 → 4。**末席漏怪 = 全队败**（没有下一家可传）。链和"换位"的环不是一回事 |
| 换位是环 | 换位 = 和后一位换，末位的后一位是首位；对面同意才生效（`SWAP_REQUEST`/`SWAP_REPLY`） |
| 无除草机 | `Board::InitLawnMowers` 黑名单里有 `IsOnlineGame()`，房子前没有兜底 |
| 波表 | 主机广播 `level + levelSeed`，两边同一份出怪基准、各按自己的节奏出波；具体出怪量再按各席位顺位缩放（见下行） |
| 出怪乘数（顺位） | 各席位自然刷怪按**上座顺位**递减（2026-10-03 用户定案，取代早先的 8:4:2:1）：四人 4:3:2:1 / 三人 3:2:1 / 二人 2:1。顺位只数**上座席位**（跳过空位，与漏怪链 `NextOccupiedSeat` 同口径）、末席最轻——前面席位漏的怪最后都压在他头上；各客户端只为自己的棋盘缩放、不涉协议。落点 `Board::PickZombieWaves`（旗帜波 ×2.5 之前，四舍五入、保底 1 点），见 `03-过程与问题.md` §5.13 |
| 判胜 | **所有上座席位**都报"草坪清完"→ 两边一起回主菜单（不发奖杯、不显示结算） |
| 全队败 | 末席漏怪 = 全队败：**两边都演"吃脑子"**（客户端不再被直接拽回菜单）。之后**只有主机**能点 Try Again——点了整队重来同一关（同关卡号、同波表种子）；主机选 Main Menu（或客户端点它）两边一起回主菜单。客户端那个框里没有 Try Again，换成一句 `The host decides whether to try again.` |
| 不写档 | 联机局不推进 `mLevel`、不写续玩档（成长留 M4） |
| 闯关（R5） | **第一槽大墓碑**（烤字 ADVENTURE）= 组队闯关入口：队伍连着时由主机起一局闯关，队友被开局命令一路拉进同一关；进度对不上（没检查点 / 检查点落后）由**补发追赶**补齐——欠下的三选一按本机这一局的种子一屏一屏补，屏数、关卡序列与主机一致，具体选什么**各选各的**（卡池两边可以不同，这是设计）。**第三槽 PUZZLE 石板**才是"一起打单关"与原版战役 |
| 闯关规则（R6） | 闯关专属、原版战役一字不动：**蘑菇种下即醒**（白天不睡）、**蘑菇售价 +25**、**咖啡豆改产 100 阳光**（4 枚 25）；**紫卡（升级植物）直接种**，售价 = 原价 + 基础植物价——机枪射手 450 / 双胞向日葵 200 / 忧郁蘑菇 225 / 冰西瓜 500 / 金磁力菇 150 / 地刺王 225 / 香蒲 250 / 玉米加农炮 600（唯一价口 `Plant::GetCost`）。水生四样（睡莲/缠绕海草/水兵菇/香蒲）在闯关里可种草坪、卡的"需要泳池/需要底座"门槛一并放行（2026-10-03 追加定案，见 `03-过程与问题.md` §5.12）；玉米加农炮仍要合法 2×2 |
| 换关时序（R6） | **先全场进草坪、再各自三选一**：命令到达 → 客户端**立刻回 `START_ACK`**（含义 = "命令收到、这就进场"）→ 主机收齐后广播 `RUN_GO` → 各席位在自己的**新草坪**上做三选一（含补发追赶）→ 选完重填卡槽、放开选卡与开场。选项屏不再盖在菜单 / 上一关残局上。时序按最多四席位写（ACK 记账扩四的账见 §六） |
| 选卡等队友 | 选完卡不再一个人先开打：本机报"我选好了"，**所有上座席位都报过才放行**——两边从同一刻起打（各按各的会越差越远）。报的是**两态状态**（1 = 选好 / 0 = 还在选，每轮草坪建好时各报一次当下值，选好了再报一次 1），只覆盖不清位——新一轮的 0 会把上一轮的 1 盖掉，不会有残留提前放行。**门口两处、按卡池分**：卡池>8 挂在 `SeedChooserScreen::CloseSeedChooser` 第一行（Let's Rock 那一刻）；**卡池 ≤8 的关卡全场不开选卡界面**（`ChooseSeedsOnCurrentLevel` 看本机卡池，两边可以不同），门挂在 `UpdateRunPick` 的 picks-done 段（三选一屏全做完就是它的"Let's Rock"：`ShowSeedChooserScreen` 报过 1 之后拦下，草坪冻着等）。放行统一由 `UpdateOnlineSeeds` 收口。等待期间草坪上挂"等待队友选卡"看板框 |
| 闯关难度（M4-a） | 一局 25 关 = 5 场景 × 5 关（关号表见 `03-过程与问题.md` §5.7）；难度按场景 ×1.2（僵尸血量与出怪点数同乘，整数千分比，两端逐位一致）；出怪 = 每波 ≤20 只 + 富余点数只抽强僵尸（价值 ≥4）+ 巨人系价值 4 / 每波合计 ≤2 / 红眼权重与普通巨人同级；种类按名单逐关加码（场景 5 屋顶剔除潜水/海豚/冰车/雪橇）；末波"全种类露面"在闯关关掉。检查点升 v2（v1 档按"没有检查点"处理） |
| 闯关时长档（M4-b） | 新局先选时长：**完整版 25 关（奖励 ×1）/ 普通版 15 关（奖励 ×2）/ 快速版 10 关（奖励 ×3）**——普通/快速 = 从 25 关表抽行（每场景第 1/3/5 关 / 第 1/5 关），奖励口径 = 每关后的奖励**屏数**倍乘（开局选卡不倍乘）；选模式页只有**主机**过（选模式页 UI 见 `RunModeDialog`），队友由 `START_LEVEL` 的 u8 `runMode` 字节带动对齐（`AlignRunToHost`：档位不同 = 删档按主机的档重摆）；检查点升 v3（低字节存档位，v2 档按完整版续），见 `03-过程与问题.md` §5.8 |
| 开局流程 | **房主开始 → 队友确认 → 一起进**：主机点开始后菜单上挂"等待其他玩家"看板框，队友弹"是否加入"询问框，点了"加入"两边才进场；点"暂不"主机收到"队友暂不加入"。非闯关局两边各有约 6 秒等待上限（到点两边一起作废，队友不会被落单）；闯关局的等待不设时限、只认掉线（队友可能在补发追赶） |
| 暂停 | 共识模型：任一方能暂停、也能继续；只同步 ESC 那条路（`DIALOG_NEWOPTIONS`）；联机环境（含建房等待，`IsActive()`）切出去/最小化不自动暂停 |
| 退关 | 一方回主菜单，对面跟着回；会话留着，主机直接点 PUZZLE 石板就能开下一局 |
| 掉线 | 心跳 1 秒一次，**5 秒**收不到判死；局中掉线 → 提示死因 + 回主菜单 |

## 二、怎么联机（操作）

0. 启动后在主菜单会先弹一次**玩法公告**（每次启动都有，「知道了」关掉；文案见
   `LawnApp::UpdateStartupAnnounce`）。
1. **两台机器最好 pull 同一提交**（见 §四）。各自 `git pull` + 重新构建 + 覆盖 exe；
   构建代次不同也连得上（只挂个提醒），但"两边行为一致"只在同版本下成立。
2. 主机：主菜单点**主位那块大墓碑**（烤字是 ADVENTURE——它现在是**组队/闯关入口**，
   牌子上的字是美术烤死的，别当 bug 修）→ **Host**。面板状态行会显示本机 IP 和端口 **27777**；
   首次监听 Windows 会弹防火墙授权，**要点允许**。
3. 队友：点**同一块大墓碑** → 在 Host IP 框里输主机的地址（回车等于点 Join）→ **Join**。
4. 连上后面板自动收起；左上角的小状态条接着显示名册和状态，点它可以再把面板叫出来。
5. 开局前可点 **Swap** 和后一位换位置（要对面按 Accept）。
6. 主机在主菜单点**第三槽的 PUZZLE 石板**（M2 的"一起打单关"走它；没队友时它是单机原版战役）→
   主机这边挂"等待其他玩家"看板框（停在菜单上，不黑屏），队友那边弹"房主开始了游戏 / 是否加入？"
   的中文询问框——**队友点了"加入"两边才一起进**；点"暂不"主机收到"队友暂不加入"的提示。
   非闯关局两边各有约 6 秒等待上限，到点一起作废（不会有"主机不等了、队友还进场"的落单）。
7. **组队闯关（R5；M4-b 起先选时长档）**：队伍连着时，主机点**第一槽的大墓碑** →
   有没打完的检查点先弹"继续闯关？"（继续 = 按原档续打；新开一局 = 进选模式页），
   没有则直接进**选模式页**（完整版 25 关 / 普通版 15 关 / 快速版 10 关三张卡片，取消 =
   不开局）→ 起一局闯关（每关后三选一，普通/快速档奖励屏 ×2/×3）。
   队友被自动拉进同一关：同一局种子、同一关序号、同一时长档；队友没检查点或落后
   （档不对也算），会先"补发追赶"
   （把欠下的三选一按本机这一局的种子补完——屏数和关卡序列与主机一致，选什么各选各的；
   R6 起是在**自己的新草坪**上补，见 §一「换关时序（R6）」）。
   队友**从菜单被拉进闯关**（起第一关 / 中途加入）同样先弹"是否加入"的询问框；局中换关不再问
   （那是正常推进），换关等待期间草坪上挂一句 "Waiting for your teammate..."。
   等待期间主菜单留在屏幕上但按钮按不动（防手滑开别的页面）。
8. 关卡里：ESC = 同步暂停；Menu → Main Menu = 两边一起退关。
9. 全队败（末席漏怪）：两边都演"吃脑子"，然后**只有主机**能点 Try Again——点了两边重来同一关
   （闯关局里 = 重打当前这一关，不推进进度）；主机不点、选了 Main Menu，两边一起回菜单
   （会话还在，直接再开一局）。

| `LawnApp.cpp` `RequestAdventure`/`EnterRunLevel`/`UpdateRunPick` | 闯关流水线；联机换关（R6）= 主机广播 `START_LEVEL` + 等 `START_ACK`，客户端**收到命令立刻回 ACK**（"这就进场"）并寄存（`mOnlineRunStartHeld`）；主机收齐广播 `RUN_GO`（客户端存 `mOnlineRunGo`）。`NewGame` 建草坪时若还欠三选一就把选卡与开场压住（`mRunIntroHeld`，`CutScene::Update` 顶部同款早退——不压的话过场计时器会自己走完），欠下的屏（含补发追赶）由 `UpdateRunPick` 摆在新草坪上，选完重填卡槽（`Board::FillSeedBankFromRunPool`；**卡池是刚做完三选一才越 8 的**时候改为按"本关选 8 株"口径重建卡槽，`03 §5.12`）再放开 |
| `Lawn/Widget/OnlineDialog.*` | 建房 / 加入面板 |
| `Lawn/Widget/OnlineStartDialog.*` | 联机流程的中文弹窗，一张类管几副面孔：主机"等待其他玩家"看板框 / 队友"是否加入"确认框 / 主机的"继续闯关？"询问 / **启动玩法公告**（正文可多行：`\n` 手动分行）。**位图字体（main.pak 里那套）没有汉字**——正文走 GDI 系统字体（`SysFont`：源码 UTF-8 字面量转本机码页字节，`TextOutA` 画），按钮是石材按钮的原画法换字体。键盘一律吞掉（防误触把开局点掉） |
| `Lawn/Widget/OnlineStatusWidget.*` | 主菜单左上小条：名册 + 状态 + 换位请求 |
| `Lawn/Widget/LawnDialog.cpp` | `GameOverDialog` 的全队败分工：客户端隐藏 Try Again（改成一行等主机的字），主机 Try Again = `LawnApp::RetryOnlineLevel()`；Main Menu = `DoBackToMain()` 顺带广播退关 |

## 四、版本纪律（最容易踩的坑）

- `PROTOCOL_VERSION`（=1）管"包怎么编"；**`MOD_BUILD`**（=23）管"两边行为配不配套"。
  只要改了"需要两台机器一起更新"的东西（新消息、开局/漏怪等行为）就要 +1，
  哪怕协议一个字没动（例：9 → 10 只是漏怪真的落地了，但旧包收到只会丢进日志；
  12 → 13 是全队败流程：两边都演吃脑子 + 只有主机能重开；
  13 → 14 是联机闯关：开局命令带闯关上下文，两边行为大改；
  14 → 15 是闯关规则改动 + R6 换关时序：蘑菇全醒/调价、紫卡直种、先全场进草坪
  再各自三选一——混搭时两边会演岔，所以抬代次。R6 的四条改动共用这一代次；
  15 → 16 是选卡等队友（`SEEDS_READY`）：选完卡不再各按各的 Let's Rock 直接开打，
  要等所有上座席位报"选好了"才放行——混搭时一边等一边开打，第三关后的不同步就是这么来的；
  16 → 17 是 M3 中继（会话层从固定两席位改成席位表 + 中继传输与控制帧，直连字节没变
  但中继旧构建没有）；
  17 → 18 是闯关扩完整版第一步（一局 5 关 → 25 关跨场景）：关序号口径变了、波数/难度/种类
  全变，旧构建的关卡表只有 5 格，收到 5 以上的序号会越界建错关，必须两边同版本；
  18 → 19 是局内快捷聊天（`MSG_QUICK_CHAT=16`，快捷短语 + 植物表情）：旧构建把这帧
  当没见过的消息静默丢——发的人以为喊了、队友没看见，所以两端要一起更新；
  19 → 20 是闯关时长档走联机协议（START_LEVEL 加 u8 runMode，载荷 17→18 字节）：
  混搭时旧长度的开局命令按串包断线；
  20 → 21 是联机/闯关局不吃本机档案（§5.9 修复批）：耙子与坚果包扎术的商店购买、卡槽
  升级的掉落升档、选卡器 7 行在联机/闯关局一律按"没买/没通关"算——混搭时买过耙子的
  一方每关多一次白送秒杀，明显占便宜，所以两端要同版本（同批的花园/图鉴解锁与三选一
  独立随机盐不抬代次：前者只管菜单入口，后者候选内容从不同步）；
  21 → 22 是闯关水生解除限制（睡莲/缠绕海草/水兵菇/香蒲可在草坪直接种，卡的"需要泳池/
  需要底座"门槛一并放行——后者补 R6 直种批的遗漏）以及换关卡槽刷新修复（快速版第 2 关
  植物栏不刷新）：混搭时一边能种一边种不了、卡槽两边显示也不一致，所以两端同版本
  （同批两笔提交共用这一代次，见 `03-过程与问题.md` §5.12）；
  22 → 23 是席位顺位刷怪乘数（§一「出怪乘数（顺位）」：四人 4:3:2:1 / 三人 3:2:1 /
  二人 2:1）：协议一个字没动、各客户端只缩自己的棋盘，但混搭时同一席位两边的出怪量
  不同，整个合作的难度口径对不上，所以两端同版本（见 `03-过程与问题.md` §5.13）。
- **14 这一代里加过"开局流程改版"（房主开始 → 队友点"加入"才进）却故意没 +1**：
  它两边都兼容——旧队友收到命令直接进场，等价于自动点了"加入"；旧主机照样收得到新队友的 ACK。
  反面教材是 12 → 13（两边都必须更新），判据就是"混搭时会不会演岔"。
- **构建代次不同不再拒连**（12 起，用户拍板）：包是同一套、编解码对得上，不配套的只是行为，
  所以照常连，状态行和小条上挂一句 "Builds differ (you 14 / peer 13)." 常驻提醒。
  看到这句 = 有一边没更新；出了说不清的毛病（比如漏怪没落地）先更新再排查。
- 还会当场拒连的只剩两种——它们连包都读不出来：`PROTOCOL_VERSION` 对不上
  （"Version mismatch"），或者 HELLO 包长对不上（旧构建的包，"Build mismatch"）。

## 六、M3 要动的结构性地方（本次排查留的账）

> **M3 已落地**（中继、席位表、按席位记账）：本章是 M2 当时的留账，已完成项与
> 后续安排以 [`05-联机-M3.md`](05-联机-M3.md) 为准。

- `mPeerSeat`/`mPeerName` 是单数：会话模型本身是"一个对端"。
- 每条消息 `mDstSeat = mPeerSeat`：线格式还表达不了"发给所有席位"（走中继时再定广播语义）。
- `ApplySeatSwap` 是两席位对调；换位协议要改成按请求里带的两个座次置换。
- 开局 `START_ACK` 现在只等一个；四席位要等所有上座席位到齐。R6 的 `RUN_GO`
  放行同样借这个单槽（`mHasRunGo`）：扩四时一并换成按席位记账，收齐**所有上座席位**
  的 ACK 才广播放行（现在别写死"就是那两个人"）。选卡等队友（`SEEDS_READY`）同理：
  `mPeerSeedsReady` 现在只记一个对端，扩四时换成**按席位一张表**（自己那格 = 上次发出去
  的值，别人的格 = 收下的状态），"全员选好"改判"所有上座席位那格都为真"。
- `SEAT_COUNT = 2` 是唯一"这一版开几个席位"的开关，扩四时从这里改。
