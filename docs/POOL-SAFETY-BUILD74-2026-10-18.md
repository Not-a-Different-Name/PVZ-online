## 第一批实际行为

- 新增 DataArrayCanAllocate、DataArrayTryAlloc、DataArrayValidateState，针对已审查路径使用受控分配；没有把所有旧分配调用统一改成返回空值，未审查路径仍需后续修复。
- 满池拒绝分配不改变当前对象、计数、空闲头或下一代 ID；释放槽位后可继续使用，其他活对象地址保持不变。
- 修正 PC ID 定位的有符号 16 位索引；两端拒绝陈旧 ID、空闲链整数与尚未使用的槽位。
- 子弹达到新上限时返回失败，植物、僵尸、星弹及分裂路径避免解引用空指针。**本批此时会少生成该次子弹，没有实现补发队列。** 这是一项极限过载保护，不能描述成“任何密度下子弹总量均保持不变”。
- 附件失败不转移所有权；非必要粒子 / 拖尾被标记清理，必需身体 / 头部动画保留。动画节点自行创建的临时子动画失败时自行清理，避免反复重试挤满动画池。
- 对已识别的附件返回值调用方补检查，避免挂接失败后在偏移、颜色等设置中再次崩溃。

未调整僵尸数量倍率、伤害或波表，没有通过删除场上僵尸规避问题。僵尸满池等待生成仍是待实现项，前批已有拒绝生成行为并未被本轮改为排队。

## 存档处理及限制

PC：先检查数量、容量与剩余数据，再复制；检查活对象 ID 与索引一致、活数量一致、空闲链在界内且正确结束。加载前预检所有池段，避免坏数量在加载一半时破坏当前棋盘。有效旧小容量池可读入新池，完整扩容棋盘保存 / 加载通过。

Android：同样检查池元信息与 ID / 空闲链；允许保存容量小于当前容量；对象长度先与所在数据块剩余长度比较，再分配临时数组；修复 DataReader 读取长度相加可回绕的问题；附件效果数量超界直接拒绝。

本轮不是整个原始快照格式的全面安全重构，未验证每个原始指针、每种动态资源尾段或全部玩法字段。PC 原始快照格式版本和角色结构布局未变。使用超过旧上限的存档不保证能降级回旧版读取；更新前由部署脚本备份原存档，玩家档案与关卡存档不主动清除。

## 性能与内存计算

机器：Ryzen 9 7945HX、16 核 32 线程、约 31.22 GiB RAM；PC x86 Release。每组 30 次预热、300 次测量，普通僵尸、30 株植物与固定存活的普通子弹。准备子弹位置不计时；逻辑更新不含完整绘制、声音和网络。

| 僵尸 / 子弹 | 逻辑更新中位数 ms | P95 ms | P99 ms |
| --- | ---: | ---: | ---: |
| 100 / 100 | 0.162 | 0.216 | 0.340 |
| 300 / 300 | 0.946 | 1.355 | 1.780 |
| 600 / 600 | 3.387 | 4.749 | 5.263 |
| 850 / 850 | 6.075 | 8.561 | 9.074 |
| 600 / 100 | 0.894 | 2.145 | 2.293 |
| 100 / 600 | 0.575 | 0.635 | 0.873 |

逻辑步长 10 ms。850/850 的中位数占预算约 60.8%，P95 占 85.6%；前批相同规模 P99 为 10.13 ms，本批为 9.07 ms。这些短时样本会波动，不能据此声称提高了性能或保证稳定帧率，更不能外推安卓性能。

碰撞候选遍历约 Q × Z × 100 / 秒。850/850 约 7225 万次 / 秒；若僵尸和子弹同时翻倍，最坏扫描量约增至 4 倍。这是候选遍历量，不是实际命中数或 CPU 指令数。

PC 子弹每槽 4336 字节结构 + 4 字节 ID，增加 1024 槽为 4,444,160 字节，约 4.24 MiB。附件每槽 776 + 4 字节，增加 3072 槽为 2,396,160 字节，约 2.29 MiB。合计 **6,840,320 字节，约 6.52 MiB**，不包括动态粒子、动画轨道与分配器成本。物理页面按触碰计入工作集，不能把槽数组预留量直接等同于即时工作集增量。

本批压力进程私有内存约 382.6–389.1 MiB，工作集约 419.2–429.3 MiB。僵尸池仍为 1024，未改子弹中按僵尸槽索引的 1024 项命中记录。

## 下一批实现顺序

1. 动画池必需 / 装饰分类、组合预留、逐个初始化失败处理；确保保留身体、头部引用和战斗行为，再扩大支持密度。
2. 掉落奖励池的调用方审查，普通价值合并及特殊奖励暂存；验证价值、归属与寿命。
3. 僵尸生成与子弹补发队列，验证计时、波次结束、组合单位与存档；持续输入超过回收速率时需明确背压策略，不能用无限队列。
4. 按行 / 空间组织碰撞候选，验证伤害、跨行攻击、Boss、魅惑和目标优先级与原实现一致。

还需多人长局、不同植物强化组合及安卓真机内存压力验收；本轮没有生成玩家完整安装包，也没有部署服务器。
